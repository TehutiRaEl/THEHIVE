# About-Me / Updates

> **Plain words:** news from the founder — "here is what changed / what I
> decided / what I want now". Newest first. Dated, always.

## What belongs here

Founder updates: what Mac said, when he said it, in his own words wherever
possible. One update per file, named by date first (for example
`2026-11-13-vision-update.md`) so newest sorts first, with the date and the
place he said it (chat, voice call, file) at the top.

An update is read newest-first. An older update never overrules a newer one
on the same point — but an update alone does not change the record. If an
update decides a question, the decision still goes through the queue into
`docs/FOUNDER_ANSWERED`. If an update changes the direction, the vision file
(`docs/FOUNDERS_VISION.md`) still has to be updated by the founder's decision.

## How to read an update

1. Read the date. Read the newest first.
2. Ask: is this an idea, a plan, an update, a vision change, or something
   about the founder himself? Sort it — see the separation rule in
   `../../README.md`.
3. If it answers an open question, check `docs/FOUNDER_QUEUE` and file the
   decision in `docs/FOUNDER_ANSWERED` (by the founder's decision, through the
   ratification path — never by an agent deciding alone).
4. If it contradicts an older update, flag the contradiction for the founder.
   Do not smooth it over and do not pick a winner quietly.

## What does NOT belong here

- Ideas → `../ideas/` (then the pool at `../../ideas/`).
- Plans → `../plans/`.
- Drafts → `../drafts/`.
- Vision → `docs/FOUNDERS_VISION.md` (updates may point at it, never replace
  it).
- Decisions → `docs/FOUNDER_ANSWERED`.

## Rules

- Keep the founder's words as his words. Mark any agent summary as a summary.
- Never present a chat message as a decided fact. A chat yes is not a decision
  until it is recorded.
- Never delete an update. The record is the record.
