## What "abomination" means, in plain words

The founder's word: **anything that is not adequate enough for the Hive is an abomination.** That covers a thing that exists but the Hive cannot see or use; work left sitting in one AI's workspace instead of returned to the Hive; a thing assumed, guessed, censored, shortened, watered down, or cut off; a decision made in chat but never written into the record; a build claimed done without live proof; a law drafted but never absorbed; and anything else the founder has named as inadequate. An abomination is not a blame word — most of these were made unknowingly, and the founder named several of them himself. It is a work word: each item below is drafted so it can be **ratified** (the founder says yes, it is recorded) and then **resolved** (the fix is built, and the proof exists).

## How to read an item

Each item has four parts, always in this order:

- **What it is** — the inadequacy, in plain words.
- **Where it was found** — file, line, issue, or PR, so anyone can re-check it. No item without a source.
- **What fixes it** — the concrete fix. A fix that needs a founder decision says so and names the decision.
- **What proves it is fixed** — the evidence that must exist before the item can be marked resolved. A merged PR alone is never the proof; a live probe, a code read citing file + line, a test result, or a recorded founder decision is. Until that evidence exists, the item stays OPEN, however good the plan looks.

**Status words used in this catalogue:**

- **OPEN** — not fixed, not yet being fixed in a PR.
- **IN PROGRESS** — a fix is drafted in an open PR or an ordered package; not merged, not verified-live, so not resolved.
- **RESOLVED** — the fix is done AND the proof named in the item exists. Only items with evidence in hand carry this word.

**What this catalogue does NOT do:** it invents no founder decisions and no F-numbers. Draft laws are marked DRAFT. Where the record is unclear, the item says UNVERIFIED instead of guessing. Where a fix is already in an open PR, the item names the PR and still stays open until that PR is merged and verified-live — an open PR is a plan, not a proof.

3. **Fixed** — the fix is built (by the batch, PR, or founder act the item names), in the order the dependencies require. Nothing is built on a blind foundation while the halt stands, except the halt's single exception (the absorption build, open PR #245).
