### A.1 The pattern, stated plainly

**The recurring pattern is: a thing exists in the repo, and nothing in the live Hive reads it, serves it, stores it, or acts on it — while Muse, reading it in conversation, makes it *look* as if the Hive knows it.**

The availability audit (2026-11-13) names it exactly: "a file exists in the repo, and nothing in the live system reads it. The file is written. The file is merged to main. Nothing in the Worker fetches it, no route serves it, no D1 table stores it, and no brain contains it. Muse reads it in conversation and acts on it — so it *looks* like the Hive knows it. But the Hive does not know it. Only Muse does."

The founder's own words on 2026-11-13 confirm he sees it as recurring, not new: the Hive not knowing what to do with the founder's decisions is "a major hindrance and a recurring issue," and the ventures finding is "another waste and bad practice that needs to be eradicated from THEHIVE, along with any and all other like actions, inactions, thoughts, plans, or code."

The mechanism underneath the pattern, diagnosed twice before the halt, is **file-first, wiring-second**: each piece of knowledge was written as a document (correct — the record must exist), but the step that wires the document into the live system was never treated as part of "done." Documents were treated as done at "written and merged," not at "wired and verified-live" (the top of the 20-rung ladder). The closing loop — the Queen Digest, which would write learned wisdom back into Nanuet's brain — was named as the missing keystone and never built, so the loop was never closed.
