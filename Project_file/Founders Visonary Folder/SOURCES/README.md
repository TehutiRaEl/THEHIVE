# SOURCES — where founder-provided material goes

This is the drop point for anything the founder wants the hive to build from that isn't
already a repo, a chat message, or an existing doc: PDFs, book excerpts, web clippings,
research notes, screenshots-as-text, anything. There was no place for this before — this is
that place.

## The subfolders

- **`pdfs/`** — PDF documents. Claude Code can read PDFs directly (up to ~20 pages per read;
  for longer ones, note the page range you want read first).
- **`books/`** — longer works, book-length material.
- **`web-clippings/`** — saved pages, articles, or pasted web content with the source URL
  noted at the top of the file.
- **`research-notes/`** — the founder's own notes, drafts, half-formed ideas — exactly the
  kind of thing `research-to-dna` is built to triage.
- **`misc/`** — anything that doesn't fit the above; better to drop it here than not at all.

## Naming

`YYYY-MM-DD-short-description.ext` — same convention as `ACTIVE/`, `VISION/`, and
`MODIFICATIONS/` elsewhere in this folder, so everything sorts chronologically together.

## What happens to a file dropped here

Nothing, automatically — and that's intentional. A file landing in this folder is not yet
hive knowledge. The next session (or the founder, explicitly) runs it through
**`research-to-dna`**: verify what's actually true or checkable in it, classify
(verified-real / catalogued-for-later / narrative-canon / declined), distill the
*principle* rather than copy the material wholesale, and only then inscribe the result into
`FABLE_DNA.md`, `THE_CODEX.md`, a skill, or the memory log — with the source cited. Dropping
something here is "I want the hive to consider this," not "this is now law."

## One honest note on licensing (read once, not a lecture)

The founder's own writing, notes, summaries, and anything they hold the rights to — store
in full, freely; that's exactly what this folder is for. For a third party's copyrighted
work (a purchased book, an article, someone else's proprietary document): storing it here
for the founder's own reference is one thing; if this repository is public or becomes
public, committing the full text would be redistributing it, which is a different question
than personal use. The practical options, in order of safety: (1) store the founder's own
notes/summary/key-excerpts-with-citation about the source rather than its full text — this
is almost always enough for `research-to-dna` to work with; (2) if the full text genuinely
needs to be here, keep it in a private repo or a private branch rather than the public one;
(3) when in doubt, ask before committing a large third-party work verbatim. This isn't
about being precious — it's the same ownership/license gate `session-harvest` and
`research-to-dna` already apply everywhere else in the hive, applied here too.
