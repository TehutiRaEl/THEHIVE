## What went wrong, stated plainly

The prior pass (`VISION/2026-08-08-vision-llm-from-scratch-atomization-008.md`) applied
`research-to-dna`'s verification step thoroughly — checking whether Oracle Cloud really has
free GPUs (it doesn't), whether "AYINE"/"Tesseract QTN"/"ACU" exist in the repo (they don't),
whether "Necromancer/Daemon" and "TITLE XXI/XXII" were real (they weren't) — but spent almost
no effort on `research-to-dna`'s *other* real use: mining a document for genuinely new,
useful ideas the hive hasn't considered yet. Devil's advocate was applied to the document's
**claims**. It was not applied, alongside childlike wonder, to what the document could
**become** for the hive — which is what was actually asked for.

This is worth recording as its own lesson: verifying truth and mining for innovation are both
real, both legitimate uses of the same lenses, and doing one thoroughly is not a substitute
for the other. A session reading this later should not repeat the narrow reading.

## What followed

A full innovator pass, `VISION/2026-08-08-vision-llm-expansion-innovator-pass-009.md`: 15

## Learned

The correction itself is the lesson worth keeping longest: **"is this true" and "what's new
here" are both real questions, and answering only one is an incomplete reading of a request
for both.** This maps directly onto why `dual-lens` exists as a two-part gate rather than
one lens doing double duty — the same principle, now confirmed a second time by a real
session actually making the single-lens mistake it was built to prevent.
